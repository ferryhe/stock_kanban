```typescript
interface RiskManager {
  // 检查订单是否超过风险限制
  checkOrderRisk(order: Order, portfolio: Portfolio): { approved: boolean; reason?: string };

  checkPositionSize(portfolio: Portfolio): RiskMetrics;
  
  // 获取当前风险指标
  getRiskMetrics(portfolio: Portfolio): RiskMetrics;
}

interface RiskMetrics {
  totalValueAtRisk: number;      // 总的持仓市值
  maxDrawdownRisk: number;        // 当前的最大回撤风险
  concentrationRisk: number;      // 集中度风险（最大单个仓位比例）
  leverageRatio: number;          // 杠杆比例
  suitableForRiskTolerance: boolean;  // 是否符合用户风险承受度
}
```

## 🏗️ 技术方案与决策

### 认证方案选择
**方案**: Session + Cookie
**原因**:
- 与现有用户表集成简单
- 适合单一应用架构
- 会话数据存储在数据库中

**备选**: JWT（未来可扩展为分布式系统时使用）

### 密码安全
- 使用 bcryptjs 实现 bcrypt hash（成本因子 10+）
- 永远不存储明文密码
- 登录时使用恒定时间比较

### 权限模型
- 用户只能访问自己的投资组合数据
- 在每个涉及用户数据的路由中验证 userId
- 使用授权中间件统一管理

### 风险管理集成点
- **订单执行前**: 调用 riskManager.checkOrderRisk()
- **每日结算时**: 计算用户的风险指标
- **实时显示**: 在前端显示当前风险水平
